# Run the local PageIndex example

The examples use Python 3.11 in `.venv` and PageIndex 0.2.10 at the commit recorded
in `pageindex_source.json`. Each invocation indexes one document and asks one
question. It does not run the 78-document benchmark.

## Run from this folder in PowerShell

```powershell
.\.venv\Scripts\python.exe scripts/run_example.py --credentials-container sirchmunk --document Illinois_FPIF__Private-Markets-RFP-2023.02.13.pdf --question-id INV-04 --index-model gpt-6-luna --chat-model gpt-6-sol --reasoning-effort medium
```

The credential option only reads the existing container configuration. PageIndex
runs in the local Windows Python process. No container is started or changed.
The API key stays in process memory and is not written into the project. Public
document text and the question are sent to the selected OpenAI API endpoint.

Alternatively, configure `OPENAI_API_KEY` and `OPENAI_BASE_URL` in the current
process and omit `--credentials-container`. This mode has no Docker dependency.
Do not paste keys into version-controlled files or command examples.

Every invocation creates a fresh example index and makes billable model calls.
This example uses the 33-page Illinois FPIF PDF. Following the official
Quickstart, `gpt-6-luna` builds the index and `gpt-6-sol` retrieves and answers,
independent of the old container's default. Both stages explicitly use `medium`
reasoning effort, including all indexing summary calls. All retrieval and
indexing prompts come from the unmodified official SDK. The custom instructions
text and its command-line switch have been removed.

Indexing uses the official default Flash mode, full optimization and summary
concurrency limit of 64. Chat uses the official default limit of 10 model turns.
The runner no longer overrides timeouts, retry counts or output-token limits,
and leaves the optional citation prompt disabled (the official default).
Responses API is selected to support the requested medium reasoning with tool
calls; credentials and a fresh local storage directory are explicitly supplied.
The model's final answer may therefore omit structured citation tags.

HTTP request
hooks check the serialized model and reasoning fields before sending; response
hooks check the actual returned model. Only these metadata and usage are logged,
not credentials or private model reasoning. Each outbound chat request is also
checked against the exact official default instructions, which are saved as
`official_chat_instructions.txt` for inspection. Historical reports and outputs
are preserved; their earlier custom configurations are no longer the runner's
current behavior.

`run_example.py` reads the PDF and `queries.json` only. It never reads reference
answers, standards, or the verified CSV. Correct-source targeting is intentional
for this single-document smoke test and must not be used in the whole-corpus test.

## Outputs

- `outputs/example/latest.json`: location and status of the most recent run.
- `outputs/example/<run-id>/result.json`: answer, citations, configuration, timing and usage.
- `outputs/example/<run-id>/tree.json`: the generated section index.
- `outputs/example/<run-id>/tool_trace.json`: tool calls, evidence returned and final answer.
- `outputs/example/<run-id>/model_calls.jsonl`: actual response model and usage for each call.
- `outputs/example/<run-id>/wire_requests.jsonl`: model and reasoning fields from serialized HTTP requests (second and later runs).
- `outputs/example/<run-id>/official_chat_instructions.txt`: the unmodified official default chat instructions (current runs).
- `.pageindex/example-<run-id>/`: the reusable local index and page text.

The completed first run also includes a human-readable `REPORT.md`, a rendered
citation page, and post-answer verification results. These review files are not
automatically generated by the runner.

## Rebuild the environment if needed

The current environment is already installed. On a new checkout, fetch the pinned
source once and install the locked dependencies:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe scripts/fetch_pageindex.py
uv pip install --python .venv/Scripts/python.exe -r requirements.lock.txt
uv pip install --python .venv/Scripts/python.exe --no-deps ./vendor/PageIndex
```

The fetch script refuses to overwrite an existing source directory. The source
commit and downloaded archive hash are retained in `pageindex_source.json`.
